### 1.5 Makefile

```makefile
.PHONY: all build run test clean deps install

# 变量定义
BINARY_NAME=macro-recorder
VERSION?=1.0.0
BUILD_TIME=$(shell date -u '+%Y-%m-%d_%H:%M:%S')
LDFLAGS=-X main.Version=${VERSION} -X main.BuildTime=${BUILD_TIME}

# 默认目标
all: deps build

# 安装依赖
deps:
    go mod download
    go mod tidy

# 构建
build:
    @echo "Building ${BINARY_NAME}..."
    go build -ldflags "${LDFLAGS}" -o bin/${BINARY_NAME} ./cmd/macro

# 运行
run:
    go run ./cmd/macro

# 测试
test:
    go test -v -cover ./...

# 测试覆盖率
test-coverage:
    go test -v -coverprofile=coverage.out ./...
    go tool cover -html=coverage.out -o coverage.html

# 代码检查
lint:
    go vet ./...
    gofmt -l .

# 格式化代码
fmt:
    gofmt -w .

# 清理
clean:
    rm -rf bin/
    rm -rf coverage.out coverage.html
    rm -rf logs/*.log

# 运行所有检查
check: fmt lint test

# 构建所有平台
build-all:
    @echo "Building for all platforms..."
    GOOS=windows GOARCH=amd64 go build -ldflags "${LDFLAGS}" -o dist/${BINARY_NAME}-windows-amd64.exe ./cmd/macro
    GOOS=darwin GOARCH=amd64 go build -ldflags "${LDFLAGS}" -o dist/${BINARY_NAME}-darwin-amd64 ./cmd/macro
    GOOS=linux GOARCH=amd64 go build -ldflags "${LDFLAGS}" -o dist/${BINARY_NAME}-linux-amd64 ./cmd/macro

# 帮助
help:
    @echo "可用命令:"
    @echo "  make deps        - 安装依赖"
    @echo "  make build       - 构建项目"
    @echo "  make run         - 运行项目"
    @echo "  make test        - 运行测试"
    @echo "  make clean       - 清理构建"
    @echo "  make fmt         - 格式化代码"
    @echo "  make lint        - 代码检查"
    @echo "  make build-all   - 构建所有平台"
```

## 二、开发规范

### 2.1 代码风格

#### Go代码规范

**包命名**:
- 全小写,无下划线
- 简洁明了,体现包功能
```go
// 好
package recorder
package generator

// 差
package recorder_tool
package my_recorder
```

**文件命名**:
- 全小写,使用下划线分隔
```go
// 好
recorder.go
event_capture.go

// 差
recorderTool.go
Event-Capture.go
```

**函数命名**:
- 导出函数: 驼峰命名(PascalCase)
- 内部函数: 驼峰命名(camelCase)
```go
// 导出函数
func NewRecorder() *Recorder {}
func StartRecording() error {}

// 内部函数
func processEvent() {}
func validateInput() {}
```

**变量命名**:
- 驼峰命名
- 避免缩写(除非广为人知)
```go
// 好
var eventCount int
var isRecording bool

// 差
var evtCnt int
var isRec bool
```

**常量命名**:
- 全大写,下划线分隔
```go
const MAX_EVENTS = 1000
const DEFAULT_TIMEOUT = 30
```

#### 注释规范

**包注释**:
```go
// Package recorder provides functionality for recording
// keyboard and mouse events.
package recorder
```

**函数注释**:
```go
// StartRecording begins capturing keyboard and mouse events.
// It returns an error if the recording cannot be started.
func StartRecording() error {
    // implementation
}
```

**关键逻辑注释**:
```go
// Filter out small mouse movements to reduce noise
if distance < 5 {
    continue
}
```

### 2.2 错误处理

**错误定义**:
```go
import "errors"

var (
    ErrAlreadyStarted = errors.New("recorder already started")
    ErrNotStarted     = errors.New("recorder not started")
    ErrBufferOverflow = errors.New("event buffer overflow")
)
```

**错误处理**:
```go
// 好的做法
func Start() error {
    if r.isRunning {
        return ErrAlreadyStarted
    }

    if err := r.hook.Start(); err != nil {
        return fmt.Errorf("failed to start hook: %w", err)
    }

    return nil
}

// 差的做法
func Start() {
    r.hook.Start()  // 忽略错误
}
```

### 2.3 测试规范

**测试文件命名**:
```
recorder.go -> recorder_test.go
```

**测试函数命名**:
```go
func TestRecorder_Start(t *testing.T) {}
func TestRecorder_Start_Error(t *testing.T) {}
func TestRecorder_Stop(t *testing.T) {}
```

**表驱动测试**:
```go
func TestValidateEvent(t *testing.T) {
    tests := []struct {
        name    string
        event   Event
        wantErr bool
    }{
        {
            name:    "valid keyboard event",
            event:   KeyEvent{Key: 'A'},
            wantErr: false,
        },
        {
            name:    "invalid event",
            event:   Event{},
            wantErr: true,
        },
    }

    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            err := ValidateEvent(tt.event)
            if (err != nil) != tt.wantErr {
                t.Errorf("ValidateEvent() error = %v, wantErr %v", err, tt.wantErr)
            }
        })
    }
}
```

```go
events := make([]Event, 0, 1000)
```

```go
// 使用缓冲通道
eventChan := make(chan Event, 1000)

// 使用对象池
var eventPool = sync.Pool{

        return &Event{}
    },
}
```

## 三、开发工作流

### 3.1 日常开发流程

```
1. 从develop创建feature分支
   git checkout -b feature/your-feature-name

2. 开发功能
   - 编写代码
   - 编写测试
   - 本地验证

3. 提交代码
   git add .
   git commit -m "feat(scope): description"

4. 推送到远程
   git push origin feature/your-feature-name

5. 创建Pull Request
   - 填写PR模板
   - 关联相关Issue

6. 代码审查
   - 至少1人审查通过
   - 所有检查通过

7. 合并到develop
   - Squash merge
   - 删除feature分支
```

---

### 3.2 发布流程

```
1. 从develop创建release分支
   git checkout -b release/v1.0.0

2. 发布准备
   - 更新版本号
   - 更新CHANGELOG
   - 完善文档

3. 测试
   - 完整回归测试
   - 性能测试
   - 用户验收测试

4. 合并到main
   git checkout main
   git merge release/v1.0.0

5. 打标签
   git tag -a v1.0.0 -m "Release v1.0.0"
   git push origin v1.0.0

6. 构建发布
   make build-all

7. 部署
   - 上传到发布页面
   - 更新官网
   - 发布公告
```
